# V45 / V1·V2 검증 기록

## 최신 공통 보정 적용판 — 2026-10-13

V1.1.0과 V2.1.0은 `shared_three_block_power_cap12`를 기본으로 사용합니다. 공통 3구간 power 후 native 강우를 최대 12mm/10분으로 제한합니다. 두 날짜 정답으로 계수와 상한을 선정했으며 독립적인 날짜 검증 성능은 아닙니다.

| 날짜 | 모델 입력 | 예측 | 최신 V2 TC9 | 제외 | MAE mm/10분 |
|---|---|---|---|---:|---:|
| 2022-08-08 | 19:10~20:00 | 20:10~23:00 | 45/54 = 83.3% | 0 | 2.652482 |
| 2025-08-13 | 07:10~08:00 | 08:10~11:00 | 44/54 = 81.5% | 0 | 0.644851 |
| 2022-08-08 | 15:00~15:50 | 16:00~18:50 | 41/50 = 82.0% | 4 | 1.481221 |

16:00은 보정 계수를 맞춘 20:10과 다른 시각의 추가 실행이며 같은 날짜이므로 독립 날짜 검증은 아닙니다. 평가 제외는 기준 셀에 음수 NC 차분 등 품질관리 제외 픽셀이 있기 때문입니다. 54개 전체를 분모로 넣은 점수로 바꾸어 표기하지 않습니다.

추론 테스트 20개, 실제 frozen EXE 5실행(V1/V2 16:00, V1 미래 NC 없는 20:10, V2 두 보정 사례)을 통과했습니다. 두 보정 사례의 실제 ASC는 탐색 후보와 바이트 일치하며 V1·V2 16:00 ASC/PRJ/PNG도 바이트 일치합니다. V1은 미래 자료가 없는 120개 관측 NC만으로 완료했고 TC9·그래프·평가 CSV를 생성하지 않았습니다. 공통 보정의 cap, 원본 배열 불변, V1/V2 시간 이력 분리도 검사했습니다.

배포 검증의 기계 판독 요약은 [release_verification.json](release_verification.json)에 있습니다. 두 EXE의 해시, 5개 실행 사례, V1 미래 자료 미사용 검사, ZIP 전체 CRC 통과를 기록합니다. 데이터와 실제 실행 결과 배열은 Git에 포함하지 않습니다.

아래의 예전 V2.0.0 결과는 **2022 전용 보정을 모든 날짜에 사용했던 역사적 기록**입니다.

## 학습과 체크포인트

학습 완료 기록에서 총 170,280 update와 validation-selected step 85,140을 확인했습니다. 선택된 체크포인트는 전체 학습의 마지막 가중치와 다릅니다. 저장소의 실제 checkpoint SHA-256은 [checkpoint.json](checkpoint.json)에 있고, 추론 시 일치하지 않으면 로딩을 중단합니다.

학습 패키지의 `training/docs/interim_evidence.json`은 2026-10-08의 중간 기록입니다. 최신 완료 상태는 이 문서와 루트 README를 기준으로 합니다. 학습 소스의 공개용 정리는 private 기본 데이터 경로를 필수 `--root`로 바꾸고 설명문을 정리했으며, 모델·손실·sampler 등 핵심 학습 코드는 frozen V45와 대응합니다.

## 실제 EXE 검증 사례

2026-10-13 CPU 실행, PyTorch 2.2.2+cu121 기준입니다. 실행시간은 장비·I/O·프로세스 상태에 따라 달라지며 성능 기준의 일반 보증값이 아닙니다.

| 날짜 | 모델 입력 | 예측 | TC8 | TC9 적중/유효 | 정확도 | MAE mm/10분 |
|---|---|---|---|---|---|---|
| 2022-08-08 | 19:10~20:00 | 20:10~23:00 | 3회 9.280 / 10.424 / 11.103초, 평균 10.269초 | 45/54 | 83.3% | 2.800618 |
| 2025-08-13 | 07:10~08:00 | 08:10~11:00 | 6.349초, 1회라 평균 판정 대기 | 18/54 | 33.3% | 1.388592 |
| 2025-08-13, 미래 NC 없음 | 07:10~08:00 | 08:10~11:00 | 5.885초 | 계산 불가 | 표시하지 않음 | 표시하지 않음 |

각 정상 사례에서 ASC 18개, PRJ 18개, 보정 예측 PNG 18장, 그래프 18장, 평가 CSV 4개가 생성됐습니다. 미래 NC가 없는 경우 예측 파일은 보존되고 그래프 0장, CSV 4개는 헤더만 생성됐습니다.

이전 V2.0.0 로그 간소화 빌드는 2022-08-08 동일 구간에서 TC8 16.064초, TC9 45/54로 확인했습니다. 그 직전 버전과 원래/보정 예측 배열은 비트 단위, ASC·PRJ·PNG·그래프·평가 CSV는 바이트 단위로 같았습니다. 당시 변경은 로그 출력 제거와 `오차율`, `초기 로딩` 문구뿐이었습니다.

## 평가를 해석하는 방법

평가 대상은 저장된 1km EPSG:3857 ASC이며, 단위를 mm/h에서 mm/10분으로 환산합니다. 기준은 평활화하지 않은 원시 누적 NC의 인접 차분을 같은 셀로 평균한 값입니다. AWS 410/418/889의 위치만 사용하며 AWS 관측 강우량은 아닙니다. 적중은 `abs(pred-truth) <= max(1, truth*0.5)`, 종합 분모는 품질관리 후 유효 좌표·시점 수입니다.

과거 500m native 픽셀의 strict 오차율 50% 미만 평가와 현재 TC9는 격자·허용오차·0강우 처리 기준이 다릅니다. 이전 90.7%와 현재 83.3%를 같은 지표의 성능 감소로 비교하면 안 됩니다.

이전 V2.0.0의 기본 예측 보정 계수는 2022-08-08 사례에서 고른 고정값이었습니다. 실행 중 미래 NC를 보정에 사용하지는 않았지만, 계수를 선정했던 사례는 독립적 검증이 아닙니다. 해당 이전 보정을 적용한 2025-08-13은 80% 기준을 충족하지 못했습니다. 새 공통 보정도 두 사례 정답으로 선정했으므로 별도 보정 날짜에서 계수와 시간·좌표 선택을 고정한 후 새로운 날짜로 일반화를 검증해야 합니다.

## 데이터 없는 저장소 검증

이번 업로드 준비에서 추론 unittest **17개**, 실제 체크포인트 합성 입력과 독립 복원 비교, 학습 모델 검사·손실 4개 검사·패키지 검증을 통과했습니다. 정리된 저장소의 V2 소스로 실제 2022-08-08 20:10 실행도 완료했으며, 이전 배포본 대비 예측 배열 비트 일치와 ASC·PRJ·PNG·그래프·평가 CSV 바이트 일치를 확인했습니다. 이 실행의 TC8은 9.534초, TC9는 45/54였습니다.

- 실제 checkpoint의 SHA·step·strict state 복원, 합성 관측으로 추론, 독립 네트워크 직접 복원과 일치, 분위수 순서 확인.
- 입력 누적 감소 이월, 미래 파일 변경에 대한 입력 불변성, 시각 특징의 연도 경계, 결측 이력 차단.
- 합성 좌표로 ASC 1km 평균·북쪽 우선 행 순서·단위·PRJ·18시각 정렬·덮어쓰기 거부 검사. 테스트가 개인 작업 폴더나 외부 좌표 데이터에 의존하지 않도록 변경.
- 저장 ASC의 실제 단위, 54개 평가 쌍, 기준 0과 경계값, 음수·결측 제외, CSV 생성, 미래 자료 누락 처리.
- 동일 조건 3회 평균 TC8 판정과 조건 불일치 분리.
- 학습 패키지의 모델 구조 검사, 손실 4개 검사 및 source/package 검증.

추론 로직은 배포본과 동일합니다. 데이터 없는 검사 통과는 실제 강우 예측 정확도를 대신하지 않습니다.
