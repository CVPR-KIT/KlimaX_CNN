# 적용 범위와 추가 학습 안내

## 1. 3개 지점 이외에도 처리할 수 있나요?

**현재 모델은 3개 지점만 예측하는 모델이 아닙니다.** 상세 영역 전체의 100×100 격자(500m, 약 50×50km)에 대해 미래 3시간의 강우량 지도 18개를 예측합니다. AWS 410·418·889는 이 지도에서 정확도를 확인하기 위해 선택한 **평가 위치**이며 모델 입력을 이 세 지점으로 제한하지 않습니다. V1과 V2의 예측 지도는 같습니다.

| 요청 | 현재 지원 상태 | 필요한 작업 |
|---|---|---|
| 같은 상세 영역의 다른 위치에서 예측값 확인 | 저장된 지도에 해당 위치의 예측값이 있음 | ASC를 GIS에서 조회하거나 좌표별 추출 기능 작성 |
| 다른 지점의 정확도·표·그래프 자동 생성 | 배포 V2는 지정한 3지점으로 고정 | 좌표 설정, 평가 개수 검사, CSV 집계, 로그, 그래프 함께 변경 |
| 영역 전체의 정확도 평가 | 배포 TC9는 3지점 평가 | 격자 전체 평가 기능 추가; 동일 격자 정답 및 품질관리 적용 |
| 다른 지역이나 전국 예측 | 현재 배포 모델의 검증 범위 밖 | 데이터 crop·좌표·전처리·모델 적용 계약 재설계 및 학습·검증 |

### 다른 평가 지점을 추가하는 절차

1. **위치 확인:** 새 지점의 위도·경도가 현재 상세 출력 영역 안에 있는지 확인합니다. 광역 400×400km 입력 영역에 있다고 상세 예측이 제공되는 것은 아닙니다.
2. **좌표 준비:** [stations_tc.json](../inference/stations_tc.json)에 사용할 ID·이름·위도·경도를 정의합니다. 현재 이 파일은 410·418·889를 지정합니다.
3. **평가 코드 확장:** [tc9_evaluation.py](../inference/src/tc9_evaluation.py)는 3개 서로 다른 지점을 요구하고 전체 비교 수를 54개로 기록합니다. 이를 지점 수 N에 따라 N×18개로 계산하도록 변경해야 합니다.
4. **표시·그래프 확장:** [v2_main.py](../inference/v2_main.py)의 3지점·54행 표시와 [tc_station_graphs.py](../inference/src/tc_station_graphs.py)의 3개 기록 및 ID 순서 검사, 고정 3패널 배치를 함께 수정합니다. **JSON에 지점만 추가해서 현재 EXE를 그대로 실행할 수는 없습니다.**
5. **매핑 검증:** 위경도를 EPSG:3857 출력 격자에 대응시키고 격자 중심 거리, 행·열, 영역 내 위치를 검증합니다. 현재 exporter와 같은 격자 정의를 사용해야 합니다. 여러 지점이 같은 ASC 셀에 대응하면 같은 예측·정답 쌍이 반복될 수 있으므로 중복 셀의 집계 정책도 정합니다.
6. **정답·판정 검증:** 같은 시각의 원시 NC 차분을 저장 ASC와 동일한 1km 격자로 평균해 비교합니다. 결측·음수 차분 등 품질관리 제외를 유지하고 새 지점의 표·그래프·분모가 일치하는지 검사한 뒤 EXE를 재빌드합니다.

새 위치에서 예측값을 조회하는 것과 그 위치의 정확도를 검증하는 것은 별개입니다. 현재 정답은 **NC 기준 격자강우**이며 AWS 실측 강우를 읽지 않습니다. AWS 관측으로 평가하려면 별도의 관측 데이터 읽기, 시간·단위 정렬 및 품질관리가 필요합니다.

PNG는 상세 500m 예측 지도이며 ASC는 EPSG:3857의 1km 평균 격자, 저장 단위 mm/h입니다. 내부 강우 및 평가 단위 mm/10분과 구분해야 합니다. 외부 위치를 가장자리 격자로 대신 조회해서 그 지역을 예측했다고 해석해서는 안 됩니다.

다른 지역에 적용할 때 좌표 파일만 교체하면 안 됩니다. 현재 crop은 고정이며 학습된 위치 파라미터도 있습니다. 새 지역의 좌표·데이터 기하와 모델 입력을 함께 맞추고 별도 성능 검증이 필요합니다.

## 2. 최신 저장소에서 전처리부터 학습할 수 있나요?

**지원하는 원본 NC만 별도로 준비하면 가능합니다.** 2026-10-14에 전처리·품질검사·새 모델 학습·계약 생성·추론 연결을 추가했습니다. 설치와 실제 단계별 명령은 [END_TO_END.md](END_TO_END.md)에 있습니다.

| 단계 | 최신 Git 소스 |
|---|---|
| 원본 NC → 일별 NPZ·좌표·검사 manifest | `pipeline.py prepare` |
| 임의 규모의 검사 완료 자료로 scratch 학습 | `pipeline.py train` |
| 검증 지표에 따른 가중치 선정·계약 생성 | 학습 결과 `best.ckpt`, `model_contract.json`, `inference_config.yaml` |
| 새 모델 예측·저장 | `pipeline.py predict --config ...` |
| 예측 저장 후 정답 평가 | `pipeline.py evaluate --config ...` |

새 경로는 데이터·생성 결과를 Git에 포함하지 않으며 원래 실험과 다른 표본 추출·학습 예산을 사용합니다. resume와 fine-tuning은 미지원입니다. 다른 지역 적용, 추가 평가 지점 및 예측 성능 보장은 1절의 범위와 별도로 검증해야 합니다. 기존 배포 EXE는 자동 갱신되지 않습니다.

## 3. 보존한 역사적 학습 runner와의 차이

**아래 제약은 과거 `train_v45.py` 경로의 설명입니다.** 새 `train_pipeline.py` 경로에는 데이터 규모·seed·epoch 고정 검사가 없고, `prepare_data.py`가 새 manifest·index를 생성하며, 생성한 모델 계약으로 source 추론에 연결할 수 있습니다.

**모델 구조는 학습 가능하며 학습 소스를 제공합니다.** [training/](../training/README.md)에 모델·데이터 loader·손실·optimizer·학습 runner가 있습니다. 그러나 **배포 V1·V2 EXE에는 학습 기능이 없고**, 저장소를 내려받는 것만으로 새 데이터 학습이 바로 실행되지는 않습니다.

현재 모델은 `MotionCoreNowcaster`를 사전학습 가중치 없이 처음부터 학습한 결과입니다. 제공 runner도 scratch 학습 경로이며 기존 checkpoint에서 재개하거나 미세조정하는 CLI 옵션은 없습니다. 기존 가중치로 추가 학습하려면 초기 가중치 복원, optimizer·scheduler 상태 및 학습 재개 정책을 구현·검증해야 합니다.

### 학습에 필요한 데이터

| 항목 | 요구 내용 |
|---|---|
| 일별 상세 강우 | `rain`: [144,100,100], 500m, mm/10분 |
| 일별 광역 강우 | `context`: [144,200,200], 2km, mm/10분 |
| 광역 유효도 | `valid`: [144,200,200], uint8 0~255 |
| 학습 window | 관측 6시점과 미래 정답 18시점; 미래 정답은 손실 계산용 |
| 감사 manifest | 날짜별 train/val 분리와 사용 가능한 window 목록 |
| sampling index | 학습 window별 날짜·기준 시점·표본 가중치 |

실제 데이터와 원래 manifest·index는 이 저장소에 포함하지 않습니다. 새 `prepare_data.py`가 별도의 감사 자료를 생성하며 원래 birth index를 재현했다고 주장하지 않습니다. 단순히 누적 NC를 학습 폴더에 넣는 것으로 위 형식이 준비되지 않습니다. 정확한 데이터 계약은 [DATA.md](../training/docs/DATA.md)에 있습니다.

### 역사적 runner 학습부터 EXE 배포까지

1. **데이터 준비:** 단위·시간·좌표·전처리를 통일해 일별 NPZ를 만들고 학습/검증 날짜를 분리합니다. 정답과 누적 NC 차분의 관계, 결측·음수 처리 및 상세/광역 정렬을 검사합니다.
2. **manifest·index 준비:** 검증된 window 목록과 sampling index를 생성합니다. `audit_pass`를 임의로 true로 적는 것은 데이터 검증을 대신하지 않습니다.
3. **runner 설정:** 현재 [train_v45.py](../training/source/experiments/scripts/train_v45.py)는 원래 실험의 학습 90,823개·검증 815개·sampler 136,235개를 엄격히 검사하고 seed 4401·20 epoch를 요구합니다. 새 규모나 설정에는 이 검사와 표본 추출·학습 스케줄·준비 기록을 함께 조정해야 합니다. 범용 trainer로 구현되어 있지는 않습니다.
4. **환경 및 기본 검사:** 원래 학습 환경은 Linux, Python 3.10.12, PyTorch 2.0.1+cu118, Lightning 1.9.5, L40S GPU입니다. 다른 환경은 별도 호환성 확인이 필요합니다. [학습 README](../training/README.md)의 모델·손실·패키지 검사를 먼저 수행합니다.
5. **짧은 학습 확인:** `--mode smoke`로 8 update를 실행해 기울기·입력·복원·분위수 순서를 확인합니다. 현재 공개 소스의 위치에서 새 기록을 생성해야 합니다.
6. **본학습:** `--mode prepare`로 준비 기록을 만들고 `--mode train`으로 학습합니다. 원래 데이터 계약을 그대로 사용하는 명령은 학습 README에 있습니다. 다른 데이터에서는 3단계의 변경과 재검증을 먼저 완료합니다.
7. **checkpoint 선정:** 독립 검증 데이터의 성능으로 모델을 선택합니다. 현재 runner는 CSI 0.1·CSI 0.5·장기 리드 CSI 0.5를 결합해 선택하며, 이는 배포 TC9의 3지점 적중률과 다른 지표입니다. `DONE.json`의 `best_path`를 확인합니다.
8. **추론 연동:** [runtime.py](../inference/src/runtime.py)의 기본 경로는 현재 checkpoint의 SHA-256과 step 85,140을 고정 검사합니다. 새 가중치로 파일만 바꾸면 로딩 오류가 납니다. 최신 source는 새 runner가 생성한 명시적 모델 계약으로 새 hash·step·좌표를 검증하는 별도 경로도 지원합니다. 역사적 runner의 파일을 수동 연결할 때는 새 모델의 구조·입력 계약·state 복원을 먼저 검증해야 합니다.
9. **보정 및 독립 평가:** 새 모델에는 기존 power 계수가 적합하다고 가정하지 않습니다. 보정 선정과 최종 평가 데이터를 분리하고 강우 강도별·전체 지도 성능도 확인합니다. 최종 평가 정답으로 계수를 선택하면 독립 성능 검증이 아닙니다.
10. **재배포:** 새 checkpoint로 source와 frozen EXE의 결과 일치를 확인하고 V1·V2를 재빌드합니다. 저장 파일·시간 정렬·품질관리·평가 분모를 검증한 뒤 버전과 설명을 갱신합니다.

### 현재 결과를 해석할 때

현재 공통 보정은 2022-08-08 20:10과 2025-08-13 08:10의 정답으로 계수를 정했습니다. 두 사례의 종합 적중률 83.3%와 81.5%는 모든 지점이나 다른 날짜에 대한 정확도 보장이 아닙니다.

추가 7날짜의 기존 결과를 분석하면, 3개 위치에서 기준강우 >0인 시점만의 적중률은 104/153=68.0%, 기준강우 ≥1mm/10분에서는 5/26=19.2%였습니다. 강도 경계 분류에만 1e-5mm 수치 오차를 허용했으며 공식 적중 판정은 변경하지 않았습니다. 공식 허용오차 `max(1mm/10분, 기준강우×50%)` 때문에 약한 비·무강우가 많으면 점수가 높아질 수 있습니다. 추가 날짜가 모델 학습에 포함됐는지는 확인되지 않았으므로 독립 학습 holdout 성능으로 주장하지 않습니다.

현재 가능한 기능, 앞으로 구현 가능한 확장, 실제 검증된 성능을 구분해 사용해야 합니다.
